# Session Sidebar Documentation

## Architecture & Layout

- `SessionSidebar.tsx` orchestrates sidebar components and lifecycle; core state and rendering logic lives in focused hooks and components.
- Layout (web/desktop): the session list starts at the top of the sidebar. Chrome and session cards share a `0.5rem` (`px-2`) gutter; the session scroller is full-width so its overlay scrollbar sits on the sidebar edge. Rows pad their content another `px-3` inside that gutter for the hover fill, so the content line sits `1.25rem` (`sidebarContentInsetX`) from each sidebar edge. Chrome without a fill aligns its icons to that content line, not to the gutter: the New session icon and the first and last icons of the `SidebarHeader` toolbar (`size-4`, like row icons) and of the hide-sessions toggle all sit on it, while bordered chrome such as the search field stays on the gutter. The chrome does not move between view modes: New session keeps one icon gap, so in folder mode its label sits 2px left of the folder names (the tree uses a wider gap). `SidebarNav` only moves further in to clear OS window chrome or the titlebar overlay. It shares the header height and vertical centering of the content-area session title. On dedicated mobile (phone drawer), New session is a full-width floating button docked at the sidebar bottom, above the session list over a sidebar-toned fade, not a `SidebarNav` row or a FAB on the drawer scrim. While worktree tasks exist, the Background tasks control floats immediately above it and opens the shared task list. The scroller keeps `pb-32` on mobileVariant so the last rows clear both controls. The button stack hides while the bulk-selection bar owns the bottom edge. The tablet sidebar keeps the `SidebarNav` control instead.
- **Project zones & session lists**: Project zones display their owned sessions in a unified recency and lifecycle order with per-row branch markers. Sessions created with "Don't work in a folder" have no project owner. They appear only in All sessions with a neutral theme-aware row shade and the "No folder" label. Folders render after loose sessions.
- In workspace mode, folder and project identity belongs to `SidebarSpacesBar`, above the session scroller. Git projects expand linked worktrees as indented branch rows. The project row targets the primary checkout; a worktree row targets that linked checkout. Both filter the session list by authoritative directory ownership, while the worktree remains owned by the registered project and never becomes a separate project. The session list never paints a duplicate sticky folder identity in workspace mode. Collapsed projects show an aggregated busy/unseen indicator (`ProjectAggregateStatusIndicator`), derived from the live status index and notification store scoped to the project's directories.
- **Activity indicator**: While a session is running (`busy`/`retry`), the row shows a working indicator (placement under "Sidebar view modes") and elapsed turn time. When a background session finishes a turn, the relative timestamp is replaced by a foreground unread dot until that session is opened. Aggregate indicators for collapsed folders and projects show a spinner while any child is running, or the unread dot when a finished turn is still unseen.
- Session rows are two-line cards, or compact single lines in folder mode (anatomy under "Sidebar view modes"); titles are bold while unread. Fork families use the same theme-aware tinted row backgrounds on desktop, tablet, and mobile. The active session uses the selection fill only; the title color does not change. Session rows do not show files-changed or diff counts. Hovering a row swaps the relative timestamp (or live status) for the archive action in the same slot so the title does not shift. Session rows do not open hover or long-press tooltips; the visible title and meta are the only session summary.
- Folders render **flat** after loose sessions: nested folders display at one level with a "Parent / Child" path label (`SessionFolderItem.displayName`); collapsing a folder hides its whole subtree.
- Archived sessions are not shown in the web/desktop sidebar; the Archive dialog (`ArchiveView`, `useUIStore.isArchivePageOpen`) replaces the old toggle. Restore (unarchive) is available per session (row context menu, Archive dialog row) and in bulk (selection bar) and writes `time.archived = 0`.
- Directory loading is catalog-driven: `PiSessionCatalogFeeder` fills every known project/worktree directory (deduped by sorted signature) through the catalog's at-most-2-in-flight scheduler. The catalog keeps each successful directory snapshot independently, so activating or opening a session in one project never removes sessions belonging to another; a failed directory refresh preserves that directory's prior rows and flips only its list status. The session list stays mounted while the sidebar is closed so opening it can slide with `transform` instead of remounting the tree. Close collapses layout width immediately, in the same 200ms easing as the header title spacers, so the session title does not slide right (header reserving toggle space) and then left (sidebar width dropping). Hidden-sidebar subscriptions still gate on `isVisible`.

## Sidebar view modes

The sidebar organization mode comes from `useUIStore.sidebarViewMode` (server-persisted `sidebarViewMode` UI setting):
- **Workspace mode** (`workspace`): Scopes one folder at a time through the folder rail. It is the only mode that mounts `SidebarSpacesBar`.
- **Folder mode** (`folder`): Renders `SidebarFolderTree`, displaying every project folder with its sessions nested underneath; multiple folders are visible at once. Collapsed folders mount no session rows (zero session subtrees mounted). Folder ordering is the project order from `useProjectsStore.reorderProjects`.
- **Timeline mode** (`timeline`): Displays sessions from every folder in a single recency-sorted list split by bucket headings (Pinned, Today, Yesterday, This week, Last week, Older). It buckets only the visible page of the recency list using `timelineBuckets.ts`.

All modes read the same catalog-derived sections without extra network fetching.

Session rows take their layout from `sessionRowVariant.ts`, provided by `SidebarProjectsList` through context. Workspace and timeline modes use `card`; folder mode uses `tree`, a compact single-line row (title and timestamp only, no details line) whose hover/selection chrome spans the full sidebar width while a leading gutter (the folder header's icon width) starts the content under the folder label. `tree` session rows and session-shaped actions (show more, new session) share `treeRowSpacingClassName`, which matches the folder header padding so every row in the tree has the same height and spacing. On touch layouts the global 36px button floor (`mobile.css`) already sizes each row's inner button, so tree rows, folder headers, and session-shaped actions carry `data-sidebar-tree-row` and drop their own vertical padding there; every row stays one 36px target instead of the floor plus padding. The trailing status is vertically centered on the row so it stays on the title line at either height. Folder names and session titles share the normal weight; a folder reads apart from its sessions through color: folder names use the full foreground, while `tree` session titles are muted until hovered, active, or needing attention. A folder header always shows the folder icon on the left and the collapse chevron on its right edge; hover actions (folder menu, new session) appear beside the chevron rather than replacing it. On touch layouts (`alwaysShowActions`) the actions stay visible and the chevron reserves a wider slot for their 36px touch targets. Offsets in the header that are not plain spacing classes multiply by `--padding-scale` themselves, so they follow the user's padding setting like the classes around them. Only expanded folders get a sticky header: a collapsed folder is as tall as its header and has nothing to stick over, and the scroller tracks every sticky box and scroll-state container on each scroll frame, so a long list of collapsed folders must not carry them (guarded in `SidebarProjectsList.test.tsx`). A sticky header covers the scroller's top padding so no row shows above it while stuck, and rows passing under it fade out; the fade keys off a `scroll-state(stuck: top)` container query (`oc-sidebar-sticky-header` in `index.css`), which Chromium supports (desktop app, Android WebView, Chrome/Edge). Engines without it (iOS WebKit, Firefox) keep the cover and get a hard edge instead of the fade.

Row anatomy: the title line carries the title and the trailing status (timestamp or unread dot, positioned over the row with an invisible spacer reserving its width); `tree` rows stop there. `card` rows add a smaller, quieter details line split to both edges: mixed lists (timeline, workspace "All sessions") lead with the folder name and push branch, PR, subtask count, agent, and working time to the right; a workspace list scoped to one folder leads with the branch and pushes the rest to the right. Whatever does not fit truncates with an ellipsis.

Working indicator: shown only while the session is streaming. `card` rows overlay it on the right edge, on top of the row, as a soft primary glow that breathes in from the edge (`oc-session-row-working-aura`, opacity-only, off under reduced motion) with the indicator standing where the timestamp is and the elapsed turn time stacked beneath it where the details line ends: nothing beneath it moves, and the `oc-session-row-working-fade` mask (`index.css`) fully hides the content under the overlay and fades the content next to it. The turn time lives in the overlay rather than the details line so a turn starting or ending never reflows the row; it falls back to the details line only when the overlay is suppressed (quick actions pinned visible). rows with hover quick actions drop the fade and the indicator while hovered or focused. `tree` rows show it in the leading gutter instead.

## File summaries

### Components

- `SidebarHeader.tsx`: Top header UI for add-project, session search, selection mode, and archive access. Projects retain their manual order; there is no sidebar display/sort menu. On dedicated mobile the toolbar occupies `var(--oc-header-height, 56px)` with `px-2` / `size-9` round icon buttons (`size-4` icons) so the chrome matches the chat header height without oversized sidebar type. Add folder / Add project still go through `sessionEvents.requestDirectoryDialog()`; dedicated mobile mounts `SessionDialogs` so the explorer overlay actually opens.
- `SidebarSpacesBar.tsx`: All sessions / project-folder / linked-worktree / Add folder rows share one row class (`px-3`, mobile `py-1.5`) so icons line up with each other and with session rows. The rail highlight and list scope (`selectedSpaceId` / `selectedWorktreePath`) live in `stores/useSidebarSpaceStore.ts` — not component state — so folder navigation outside the rail (keyboard folder-cycle shortcuts) moves the rail exactly like a rail click. Selecting a session row never changes it. Folder reorder handles stay `size-4` and do not take dnd-kit `role="button"` attributes, which would inherit the mobile 36px min touch target and indent the icon. Linked worktree rows expose a `Close worktree` context action on right-click and a 500ms long press, including tablet/mobile surfaces; the confirmation dialog blocks close while that worktree has a live session.
- `SidebarNav.tsx`: Text-style New session control (no row chrome or hover background; label brightens on hover) plus hide-sessions control above the tree; hidden on the dedicated mobile phone sidebar, which uses a floating New session button docked at the sidebar bottom instead. On desktop the top strip is a window-drag region with a no-drag carve under the persistent PiChamber menu overlay so Electron cannot steal those clicks while the sidebar is open.
- `SidebarFooter.tsx`: Static footer with icon-only settings, shortcuts, and about actions. Hidden on mobile; those actions live in the mobile sidebar header.
- `SidebarProjectsList.tsx`: Main scrollable renderer for project zones and their flat/archived groups plus empty/search states; owns project drag-to-reorder.
- `SidebarFolderTree.tsx`: Multi-folder tree renderer for by-folder view mode with drag-to-reorder folders, collapsible folder zones, and unowned session handling.
- `SessionGroupSection.tsx`: Renders one flat (or archived) group: sessions first, then flat folder entries with path labels and session-shaped show-more/new-session rows. Empty active groups show New session; empty archived groups show an empty notice. Catalog list status drives sidebar coverage; there is no per-group bootstrap loading or retry UI.
- `SessionNodeItem.tsx`: Renders one session row/tree node as a two-line card (title line, then a details line split between folder or branch on the left and the remaining meta on the right) or, in folder mode, a compact single line, with indicators, menu actions, and nested children. Pending-question counts stay per-session while expanded and roll up hidden descendants from their owning directory stores while collapsed. Rows do not wrap the title in a tooltip or paint an inner press fill; the row selection/hover chrome is the only highlight.
- `collapsedActivityIndicator.tsx`: Aggregate busy/unseen dot for collapsed groups and folders.
- `ConfirmDialogs.tsx`: Shared confirm dialog wrappers for session delete, folder delete, and worktree close flows. Worktree close checks Git status before enabling the destructive action, requires explicit acknowledgement for dirty files, preserves the local branch, and refuses active worktrees.
- `sortableItems.tsx`: DnD sortable wrappers for project and group ordering.
- `sessionFolderDnd.tsx`: Folder/session DnD scope and wrappers for dropping/moving sessions into folders.
- `sessionOwnership.ts`: Resolves session directories once into shared project/worktree ownership and folder-scope indexes. Worktree ownership comes from Git discovery, not filesystem containment beneath the project path.

### Hooks

- `hooks/useTimelineBoundaries.ts`: Computes timeline date boundaries and schedules updates at local midnight or when visibility changes.
- `hooks/useProjectSessionSelection.ts`: Resolves active/current project-session selection logic and session-directory context. While a new-session draft is open it does not steal the view onto an existing session; the draft target follows the sidebar's active project instead. Switching a project/folder still loads that folder's remembered or first session in the background, but dedicated mobile keeps the sessions drawer open so the user can pick a different session. Opening Settings from the mobile sidebar closes the drawer.
- `hooks/useSessionActions.ts`: Centralizes session row actions (select/open, rename, share/unshare, archive/delete, confirmations). Explicit session picks still close the mobile sessions drawer; project-folder auto-selects pass `keepPanelOpen`.
- `hooks/useSessionSearchEffects.ts`: Handles search open/close UX and input focus behavior.
- `hooks/useSessionGrouping.ts`: Builds grouped session structures and search text/filter helpers.
- `hooks/useSessionSidebarSections.ts`: Composes final per-project sections and group search metadata for rendering.
- `hooks/useArchivedAutoFolders.ts`: Maintains archived auto-folder structure and assignment behavior.
- `hooks/useSidebarPersistence.ts`: Persists sidebar UI state (expanded/collapsed/pinned/project sort/active session) to storage + desktop settings.
- `hooks/useProjectRepoStatus.ts`: Tracks per-project git-repo state and root branch metadata.
- `hooks/useProjectSessionLists.ts`: Reads live and archived project buckets from the shared ownership index.
- `hooks/useAuthoritativeSessionCleanup.ts`: Establishes the first complete active+archived list as a non-destructive baseline, then cleans persisted state only for sessions omitted by a later authoritative snapshot.

### Types and utilities

- `timelineBuckets.ts`: Pure timeline bucketing logic, week-start resolution, boundary arithmetic, and O(n) item grouping.
- `types.ts`: Shared sidebar types (`SessionNode`, `SessionGroup`, summary/search metadata).
- `sessionNodeItemUtils.ts`: Memoization and extraction utilities for session node rows.
- `utils.ts`: Deduplication, search matching, path normalization, and shared row class names.
- `highlightedText.tsx`: Search highlight markup for session and group labels.
- `sidebarRowChrome.tsx`: Session-shaped row buttons.
