# Session Sidebar Documentation

## Architecture & Layout

- `SessionSidebar.tsx` orchestrates sidebar components and lifecycle; core state and rendering logic lives in focused hooks and components.
- Layout (web/desktop): the session list starts at the top of the sidebar. Chrome and session cards share a `0.5rem` (`px-2`) gutter; the session scroller is full-width so its overlay scrollbar sits on the sidebar edge. Rows pad their content another `px-3` inside that gutter for the hover fill, so the content line sits `1.25rem` (`sidebarContentInsetX`) from each sidebar edge. Chrome without a fill aligns its icons to that content line, not to the gutter: the New session icon and the first and last icons of the `SidebarHeader` toolbar (`size-4`, like row icons) and of the hide-sessions toggle all sit on it, while bordered chrome such as the search field stays on the gutter. The chrome does not move between view modes: New session keeps one icon gap, so in folder mode its label sits 2px left of the folder names (the tree uses a wider gap). `SidebarNav` only moves further in to clear OS window chrome or the titlebar overlay. It shares the header height and vertical centering of the content-area session title. On dedicated mobile (phone drawer), New session is a full-width button in a footer under the session list, not a `SidebarNav` row, a floating button over the list, or a FAB on the drawer scrim; the list ends where the footer starts, so the bottom-anchored Snoozed and Settled shelves sit directly above it. While worktree tasks exist, the Background tasks control sits immediately above the button in the same footer and opens the shared task list. The button stack hides while the bulk-selection bar owns the bottom edge. The tablet sidebar keeps the `SidebarNav` control instead.
- **Project zones & session lists**: Project zones display their owned sessions in a unified recency and lifecycle order with per-row branch markers. Sessions created with "Don't work in a folder" have no project owner. They appear only in All sessions with the "No folder" label in their details line and no row shade, since a fill would read as a second selection. Every surface names a project with `getProjectDisplayLabel` (`lib/projectDisplayLabel.ts`): a saved label shows exactly as written, and an unlabeled folder shows its name title-cased (`demo-repo` reads `Demo Repo`) in the sidebar, header, composer, switcher, command palette, Projects settings, and window title. Folders render after loose sessions.
- In workspace mode, folder and project identity belongs to `SidebarSpacesBar`, above the session scroller. Git projects expand linked worktrees as indented branch rows. The project row targets the primary checkout; a worktree row targets that linked checkout. Both filter the session list by authoritative directory ownership, while the worktree remains owned by the registered project and never becomes a separate project. The session list never paints a duplicate sticky folder identity in workspace mode. Collapsed projects show an aggregated busy/unseen indicator (`ProjectAggregateStatusIndicator`), derived from the live status index and notification store scoped to the project's directories.
- **Activity indicator**: While a session is running (`busy`/`retry`), the row shows a working indicator (placement under "Sidebar view modes") and elapsed turn time. When a background session finishes a turn, the relative timestamp is replaced by a foreground unread dot until that session is opened. When the daemon reports a session waiting on the user (`pendingInput`), the row shows a needs-input dot in the status-warning token instead: `SessionNeedsInputIndicator` replaces the unread dot in the trailing slot, and while the turn overlay is shown it takes the working spinner's place (the breathing glow is dropped, the turn time stays beneath it), so a session blocked on the user reads as waiting rather than working. `tree` rows hide the gutter spinner for the same reason. Aggregate indicators for collapsed folders and projects show the warning dot while any child needs input, a spinner while any child is running, or the unread dot when a finished turn is still unseen.
- **Attention rank** (`sessionAttention.ts`): one shared rank used by sidebar rows, collapsed rollups, the project aggregate dot, and both session switchers — `resolveSessionAttention` returns `needs-input` (daemon `pendingInput` with `count > 0`) over `working` (busy/retry) over `unread` (unseen count, only when settled and not active). Needs input is the only state that shows for the active session in lists. Labels: `Needs input` / `Needs approval`, with ` (N requests)` appended above one request; collapsed surfaces use `A session needs input` / `N sessions need input`.
- Session rows are two-line cards, or compact single lines in folder mode (anatomy under "Sidebar view modes"); titles are bold while unread. Fork families use the same theme-aware tinted row backgrounds on desktop, tablet, and mobile. The active session uses the selection fill and a medium-weight title, so the selection reads without relying on the tint alone. Session rows do not show files-changed or diff counts. Hovering a row swaps the relative timestamp (or live status) for the archive action in the same slot so the title does not shift. Session rows do not open hover or long-press tooltips; the visible title and meta are the only session summary.
- Folders render **flat** after loose sessions: nested folders display at one level with a "Parent / Child" path label (`SessionFolderItem.displayName`); collapsing a folder hides its whole subtree.
- Archived sessions are not shown in the web/desktop sidebar; the Archive dialog (`ArchiveView`, `useUIStore.isArchivePageOpen`) replaces the old toggle. Restore (unarchive) is available per session (row context menu, Archive dialog row) and in bulk (selection bar) and writes `time.archived = 0`.
- Directory loading is catalog-driven: `PiSessionCatalogFeeder` fills every known project/worktree directory (deduped by sorted signature) through the catalog's at-most-2-in-flight scheduler. The catalog keeps each successful directory snapshot independently, so activating or opening a session in one project never removes sessions belonging to another; a failed directory refresh preserves that directory's prior rows and flips only its list status. The session list stays mounted while the sidebar is closed so opening it can slide with `transform` instead of remounting the tree. Close collapses layout width immediately, in the same 200ms easing as the header title spacers, so the session title does not slide right (header reserving toggle space) and then left (sidebar width dropping). Hidden-sidebar subscriptions still gate on `isVisible`.

## Sidebar view modes

The sidebar organization mode comes from `useUIStore.sidebarViewMode` (server-persisted `sidebarViewMode` UI setting):
- **Workspace mode** (`workspace`): Scopes one folder at a time through the folder rail. It is the only mode that mounts `SidebarSpacesBar`.
- **Folder mode** (`folder`): Renders `SidebarFolderTree`, displaying every project folder with its sessions nested underneath; multiple folders are visible at once. Collapsed folders mount no session rows (zero session subtrees mounted). Folder ordering is the project order from `useProjectsStore.reorderProjects`.
- **Timeline mode** (`timeline`): Displays sessions from every folder in a single recency-sorted list split by bucket headings (Pinned, Today, Yesterday, This week, Last week, Older). It buckets only the visible page of the recency list using `timelineBuckets.ts`.
- **Threads mode** (`threads`): Lists sessions from every folder by state instead of by folder, under the same section headings as Timeline (`SidebarSectionHeading`): Pinned, Working (sessions running now), Recent (every other session, latest activity first; the heading shows only when another section is present), then collapsible Snoozed and Settled sections anchored at the bottom of the sidebar behind a divider, whose headings carry a count and chevron. Snoozed and settled rows have muted titles in every view, since they are put away. Snoozed and Settled start collapsed (the expanded set persists in localStorage under `oc.sidebar.shelves.expanded`); a collapsed section still shows the open session, and a search expands them. Settled shows 10 rows, then pages by 25. On desktop, rows drag between Pinned, Recent, and Settled (`SidebarThreadsList` owns that `DndContext`; drag within a section does not reorder).

### Session shelves

Threads and By folder share one shelf model. The per-session rule lives in `lib/sessionShelf.ts` (`resolveSessionShelfSection`): snoozed, then settled, then pinned, then working (Threads only, and not while the session waits on input), then active. A manual settle wins over a pin. A session that is working or waiting on input never sits in Settled, and only waiting on input ends a snooze early. With `sidebarAutoSettleAfterDays` set (portable UI setting, 0 = off, 1–90, default 3), a session idle that long settles unless it is pinned, working, waiting, or snoozed. A session whose snooze ran out shows `Woke` until it is opened; opening it clears the wake. Sending a message or command to a session clears its shelf entry on the server, so a session you return to rejoins the active list.

Manual state (settled, un-settled, snoozed until) is stored by the server in `<dataDir>/pi/session-shelf.json` and read through `useSessionShelfStore`, which applies updates optimistically and keeps its last entries when a read fails. Pins stay in `useSessionPinnedStore`. `sessionShelves.ts` applies the rule to a list and sorts each shelf; `hooks/useSessionShelves.ts` feeds it live working and needs-input sets (`useSessionShelfLiveState`), a minute clock that also fires at the next wake, and reloads on focus, runtime switch, and shortly after a session starts working. Rows learn their shelf through `SessionShelfRowContext` and offer Settle / Un-settle and Snooze / Wake in the menu and as a hover action; a snoozed row shows its wake day or time in place of the timestamp.

By folder uses the same shelves without the Working section: pinned sessions move to a Pinned section above the folders, snoozed and settled sessions leave their folders for shared Snoozed and Settled shelves below them, and folders stop paging (no Show more). A folder whose sessions are all shelved shows only its header, without a collapse chevron since there is nothing to collapse. Pinned and shelved rows in By folder use the `card` row with the folder name in their details line, because they no longer sit under their folder. As in Threads, the shelves sit at the bottom of the sidebar behind a divider. While a search is active, By folder shows every match in its folder.

All modes read the same catalog-derived sections; Threads and By folder also read the session shelf state (below), which is one small server file, not a per-session fetch.

Session rows take their layout from `sessionRowVariant.ts`, provided by `SidebarProjectsList` through context. Workspace and timeline modes use `card`; folder mode uses `tree`, a compact single-line row (title and timestamp only, no details line) whose hover/selection chrome spans the full sidebar width while a leading gutter (the folder header's icon width) starts the content under the folder label. `tree` session rows and session-shaped actions (show more, new session) share `treeRowSpacingClassName`, which matches the folder header padding so every row in the tree has the same height and spacing. On touch layouts the global 36px button floor (`mobile.css`) already sizes each row's inner button, so tree rows, folder headers, and session-shaped actions carry `data-sidebar-tree-row` and drop their own vertical padding there; every row stays one 36px target instead of the floor plus padding. The trailing status is vertically centered on the row so it stays on the title line at either height. A folder reads apart from its sessions through weight and color: folder names are medium weight in the full foreground, while `tree` session titles are normal weight and muted until hovered, active, or needing attention. A collapsed folder shows its session count beside the name, ahead of the aggregate status dot. A folder header always shows the folder icon on the left and the collapse chevron on its right edge; hover actions (folder menu, new session) appear beside the chevron rather than replacing it. On touch layouts (`alwaysShowActions`) the actions stay visible and the chevron reserves a wider slot for their 36px touch targets. Offsets in the header that are not plain spacing classes multiply by `--padding-scale` themselves, so they follow the user's padding setting like the classes around them. Only expanded folders get a sticky header: a collapsed folder is as tall as its header and has nothing to stick over, and the scroller tracks every sticky box and scroll-state container on each scroll frame, so a long list of collapsed folders must not carry them (guarded in `SidebarProjectsList.test.tsx`). A sticky header covers the scroller's top padding so no row shows above it while stuck, and rows passing under it fade out; the fade keys off a `scroll-state(stuck: top)` container query (`oc-sidebar-sticky-header` in `index.css`), which Chromium supports (desktop app, Android WebView, Chrome/Edge). Engines without it (iOS WebKit, Firefox) keep the cover and get a hard edge instead of the fade.

Row anatomy: the title line carries the title and the trailing status (timestamp or unread dot, positioned over the row with an invisible spacer reserving its width); `tree` rows stop there. `card` rows add a smaller, quieter details line split to both edges: mixed lists (timeline, workspace "All sessions") lead with the folder name and push branch, PR, subtask count, agent, and working time to the right; a workspace list scoped to one folder leads with the branch and pushes the rest to the right. Whatever does not fit truncates with an ellipsis. A row names a branch only when its session runs outside its folder's primary checkout (a linked worktree) on a branch other than the folder's current one (`useSessionNodeItemMetadata`); the folder's own branch is already on the header and composer, so a session in the primary checkout shows no branch and, with nothing else to show, no details line. The command palette applies the same rule to its session rows.

Working indicator: shown only while the session is streaming. `card` rows overlay it on the right edge, on top of the row, as a soft primary glow that breathes in from the edge (`oc-session-row-working-aura`, opacity-only, off under reduced motion) with the indicator standing where the timestamp is and the elapsed turn time stacked beneath it where the details line ends: nothing beneath it moves, and the `oc-session-row-working-fade` mask (`index.css`) fully hides the content under the overlay and fades the content next to it. The turn time lives in the overlay rather than the details line so a turn starting or ending never reflows the row; it falls back to the details line only when the overlay is suppressed (quick actions pinned visible). rows with hover quick actions drop the fade and the indicator while hovered or focused. `tree` rows show it in the leading gutter instead.

## File summaries

### Components

- `SidebarHeader.tsx`: Top header UI for add-project, session search, selection mode, and archive access. Projects retain their manual order; there is no sidebar display/sort menu. On dedicated mobile the toolbar occupies `var(--oc-header-height, 56px)` with `px-2` / `size-9` round icon buttons (`size-4` icons) so the chrome matches the chat header height without oversized sidebar type. Add folder / Add project still go through `sessionEvents.requestDirectoryDialog()`; dedicated mobile mounts `SessionDialogs` so the explorer overlay actually opens.
- `SidebarSpacesBar.tsx`: All sessions / project-folder / linked-worktree / Add folder rows share one row class (`px-3`, mobile `py-1.5`) so icons line up with each other and with session rows. The rail highlight and list scope (`selectedSpaceId` / `selectedWorktreePath`) live in `stores/useSidebarSpaceStore.ts` — not component state — so folder navigation outside the rail (keyboard folder-cycle shortcuts) moves the rail exactly like a rail click. Selecting a session row never changes it. Folder reorder handles stay `size-4` and do not take dnd-kit `role="button"` attributes, which would inherit the mobile 36px min touch target and indent the icon. Linked worktree rows expose a `Close worktree` context action on right-click and a 500ms long press, including tablet/mobile surfaces; the confirmation dialog blocks close while that worktree has a live session.
- `SidebarNav.tsx`: Text-style New session control (no row chrome or hover background; label brightens on hover) plus hide-sessions control above the tree; hidden on the dedicated mobile phone sidebar, which uses a floating New session button docked at the sidebar bottom instead. On desktop the top strip is a window-drag region with a no-drag carve under the persistent PiChamber menu overlay so Electron cannot steal those clicks while the sidebar is open.
- `SidebarFooter.tsx`: Static footer with icon-only settings, shortcuts, and about actions. Hidden on mobile; those actions live in the mobile sidebar header.
- `SidebarProjectsList.tsx`: Main scrollable renderer for project zones and their flat/archived groups plus empty/search states; owns project drag-to-reorder.
- `SidebarFolderTree.tsx`: Multi-folder tree renderer for by-folder view mode with drag-to-reorder folders, collapsible folder zones, and unowned session handling. With shelves it hides pinned, snoozed, and settled sessions from the folders and renders the Pinned section and the shared shelf stack.
- `SidebarThreadsList.tsx`: Threads view: Pinned, Working, and Recent sections and `SessionShelfStack` (also used by By folder), the collapsible, paged Snoozed and Settled sections, with desktop drag between sections.
- `sidebarRowChrome.tsx`: Session-shaped action rows (`SidebarSessionLikeButton`) and `SidebarSectionHeading`, the heading shared by Timeline buckets and the Threads and By folder sections.
- `sessionShelves.ts` / `sessionShelfRowContext.ts`: Shelf partition and sort for a list of root sessions, and the context rows read their shelf from. Unit-tested in `sessionShelves.test.ts`.
- `SessionGroupSection.tsx`: Renders one flat (or archived) group: sessions first, then flat folder entries with path labels and session-shaped show-more/new-session rows. Empty active groups show New session; empty archived groups show an empty notice. Catalog list status drives sidebar coverage; there is no per-group bootstrap loading or retry UI.
- `SessionNodeItem.tsx`: Renders one session row/tree node as a two-line card (title line, then a details line split between folder or branch on the left and the remaining meta on the right) or, in folder mode, a compact single line, with indicators, menu actions, and nested children. Per-row pending input comes from `useSessionPendingInput(session.id)` (an O(1) catalog lookup, same subscription shape as the live status hook) and is ranked through `resolveSessionAttention`; while it is pending, the working spinner and glow give way to the needs-input dot. Rows do not wrap the title in a tooltip or paint an inner press fill; the row selection/hover chrome is the only highlight.
- `sessionAttention.ts`: Shared attention rank plus accessible-label helpers; unit-tested in `sessionAttention.test.ts`.
- `SessionNeedsInputIndicator.tsx`: Status-warning sibling of `SessionUnreadDot` for the needs-input state.
- `collapsedActivityState.ts`: Aggregate `input` state ranked above `active` and `unread` (`getSessionNodesActivityState` takes the needing-id set, defaulting to empty). Group sections build that set once per group render from `useSessionsNeedingInput()` — never per row — and folder rollups receive it through `useSessionGroupFolders`.
- `collapsedActivityIndicator.tsx`: Aggregate input/active/unread indicator; the input branch renders the status-warning dot with an `inputLabel` prop (defaults to `Needs input`).
- `ProjectAggregateStatusIndicator.tsx`: Collapsed-project dot showing the warning state (with `A session needs input` / `N sessions need input` labels) when any of the project's sessions needs input, ahead of the busy spinner.
- `ConfirmDialogs.tsx`: Shared confirm dialog wrappers for session delete, folder delete, and worktree close flows. Worktree close checks Git status before enabling the destructive action, requires explicit acknowledgement for dirty files, preserves the local branch, and refuses active worktrees.
- `sortableItems.tsx`: DnD sortable wrappers for project and group ordering.
- `sessionFolderDnd.tsx`: Folder/session DnD scope and wrappers for dropping/moving sessions into folders.
- `sessionOwnership.ts`: Resolves session directories once into shared project/worktree ownership and folder-scope indexes. Worktree ownership comes from Git discovery, not filesystem containment beneath the project path.

### Hooks

- `hooks/useSessionShelves.ts`: Shelf partition for Threads and By folder (null for other views), its clock and reloads, and `updateSessionShelf` for row actions (failure shows a toast).
- `hooks/useTimelineBoundaries.ts`: Computes timeline date boundaries and schedules updates at local midnight or when visibility changes.
- `hooks/useProjectSessionSelection.ts`: Resolves active/current project-session selection logic and session-directory context. While a new-session draft is open it does not steal the view onto an existing session; the draft target follows the sidebar's active project instead. Switching a project/folder still loads that folder's remembered or first session in the background, but dedicated mobile keeps the sessions drawer open so the user can pick a different session. Opening Settings from the mobile sidebar closes the drawer.
- `hooks/useSessionActions.ts`: Centralizes session row actions (select/open, rename, share/unshare, archive/delete, confirmations). Explicit session picks still close the mobile sessions drawer; project-folder auto-selects pass `keepPanelOpen`.
- `hooks/useSessionSearchEffects.ts`: Handles search open/close UX and input focus behavior.
- `hooks/useSessionGrouping.ts`: Builds grouped session structures and search text/filter helpers.
- `hooks/useSessionSidebarSections.ts`: Composes final per-project sections and group search metadata for rendering.
- `hooks/useArchivedAutoFolders.ts`: Maintains archived auto-folder structure and assignment behavior.
- `hooks/useSidebarPersistence.ts`: Persists sidebar UI state (expanded/collapsed/pinned/project sort/active session) to storage + desktop settings.
- `hooks/useProjectRepoStatus.ts`: Tracks per-project git-repo state and root branch metadata.
- `hooks/useProjectSessionLists.ts`: Reads live and archived project buckets from the shared ownership index.
- `hooks/useAuthoritativeSessionCleanup.ts`: Establishes the first complete active+archived list as a non-destructive baseline, then cleans persisted state only for sessions omitted by a later authoritative snapshot.

### Types and utilities

- `timelineBuckets.ts`: Pure timeline bucketing logic, week-start resolution, boundary arithmetic, and O(n) item grouping.
- `types.ts`: Shared sidebar types (`SessionNode`, `SessionGroup`, summary/search metadata).
- `sessionNodeItemUtils.ts`: Memoization and extraction utilities for session node rows.
- `utils.ts`: Deduplication, search matching, path normalization, and shared row class names.
- `highlightedText.tsx`: Search highlight markup for session and group labels.
- `sidebarRowChrome.tsx`: Session-shaped row buttons.
