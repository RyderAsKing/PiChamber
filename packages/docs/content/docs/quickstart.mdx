title: Quick start
description: Start an authenticated PiChamber server and open its browser UI.
---

Run PiChamber on the computer that holds your projects, then connect from a
browser or another PiChamber client. Install the CLI first: [Install](/install/).

The computer running the server is the **host**. Sessions use its files, Pi
configuration, and provider credentials—not those of the connecting device.
Keep the host awake and the server running while you use it remotely.

## Start a server

For guided setup:

```sh
pichamber serve
```

Or start on a specific port with a generated password:

```sh
pichamber serve --port 3000 --ui-password
```

Save the printed password. This command runs **in the background** and listens
on `127.0.0.1` by default. Open `http://127.0.0.1:3000` on the host and sign in.
You should see your sessions and be able to start a Pi session.

Loopback (`127.0.0.1`) means **this computer only**. It is not the address to use
on your phone. Add `--foreground` if you want the server attached to its terminal.

## Check and stop

Forgot the port? List discovered instances and their ports:

```sh
pichamber status
```

Stop one server using its actual port:

```sh
pichamber stop --port 3000
```

Closing Terminal does not stop a background server. Background mode does not
configure automatic startup after reboot. If you enabled startup integration,
use `pichamber startup disable` to prevent automatic relaunch. See the
[CLI guide](/cli/) for startup, logs, and restart commands.

## Connect from another device

**Same trusted Wi-Fi: no tunnel needed.** Restart a loopback-only server with
LAN access and a new generated password:

```sh
pichamber stop --port 3000
pichamber serve --port 3000 --lan --ui-password
```

Open `http://HOST-IP:3000` on the other device. On macOS, find the host IP in
**System Settings → Wi-Fi → Details → TCP/IP**. Sign in with the new password.
LAN HTTP access is intended for trusted networks.

**Outside your network:** use a Cloudflare tunnel. LAN access and a tunnel can
run together. Follow [Connect devices](/connect-devices/) for foreground tunnel
commands, browser versus app pairing, and how to stop each kind of tunnel.

For a PiChamber-managed tunnel, shut down remote access before the server:

```sh
pichamber tunnel stop --port 3000
pichamber stop --port 3000
```

For a standalone `cloudflared` tunnel, press **Ctrl+C** in its terminal instead
of using `pichamber tunnel stop`, then stop the server separately.

## Docker

Copy `docker-compose.yml` from the repository, set `PICHAMBER_UI_PASSWORD` to a
strong password, and run `docker compose up -d`. See [Run PiChamber in Docker](/docker/)
for host port bindings, projects, persistent data, and upgrades.

If startup fails, see [Troubleshooting](/troubleshooting/).
